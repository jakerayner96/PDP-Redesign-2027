WHAT THIS MEANS FOR THE NEXT TESTS

ONE CHANGE AT A TIME

01

Too many moving parts

In Home and Beauty, lots of modules moved at once, so it was hard to understand what caused the drop.

02

More atomic tests

Future tests need to change one thing at a time and measure its impact.

03

Test and redesign together

That is harder when the PDP format and UI are changing at the same time, so the test plan and redesign need to work in tandem.

WHAT HAPPENS NEXT

PRINCIPLES FOR THE NEW PDP

Prioritise the info that helps someone decide to purchase this product over anything else on the page.
Every module has a job, an owner and a metric. We continuously measure at a granular level of detail (each click/tap, scroll etc.)
One framework, one design system: layouts per category and UI themes per brand.
Delivery, returns, promotions and payments each appear clearly, once, in a purpose designed position, not repeated.
Test anything that touches profit and deliver+ uptake, check attach rates in every test.
Where the problem is in the data, fix the data. This is a key enabler prior to the new PDP going live.
Ship on web first, then fast follow on app once value is proven, if not start to test on app. Ensure the same components are used app as are used on web (unless native nuance justifies), enabling operational efficiency and pace of delivery, as well as a consistent experience for users.
WHAT HAPPENS NEXT

CONCEPTS, WORKSHOPS, TESTS

01

Concept phase

UX to explore multiple designs, prototypes and concepts for every fascia and the different product types across Home, Fashion and Beauty, on mobile, desktop and app, built on the group design system, before reviewing and feeding back with the team.

02

Ideation & benchmarking workshops

Starting with the UX, Tech and Product team, then expanding to brands if required. We share examples of what good looks like, discuss what might be worth exploring and review the designs and concepts created by UX.

03

A/B & CRO test plan

UX will work hand in hand with the Experimentation team to break the concepts we progress into a robust testing plan, with the team involved from the outset.
